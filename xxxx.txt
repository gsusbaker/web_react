Práctica 11
Partiendo de las especificaciones de la anterior práctica, realiza las siguientes mejoras
sobre la página web.
● En la página de detalles de un videojuego deben mostrarse como mínimo:
○ Tags (No confundir con género)
○ Publisher
○ Plataformas
● Cada tag/género debe ser clickable y debe llevar a una nueva página que muestre
los juegos de un tag/género
● Cada publisher será un enlace que llevará una página con información sobre el
publisher y sus videojuegos
● Añade paginación a la página de lista de videojuegos.
○ Importante. Se tiene que controlar la paginación desde la propia URL/ruta de
la página. Es decir, si accedo a miweb.es/juego/ , tengo que poder realizar lo
siguiente: miweb.es/juego?page=4 y que cargue directamente la 4º página de
la lista de videojuegos, ya sea de los populares, por un tag ya dado/, un
término de búsqueda, etc…
● Crea una nueva página similar a la principal de videojuegos, pero donde se
buscarán Publishers
Estructura recomendada para el proyecto
Se recomienda seguir la siguiente estructura para el proyecto dentro de src:
● Carpeta pages/views: carpeta con las páginas/vistas de tu web
● Carpeta components: carpeta con componentes o fragmentos de elementos que
uses en tu página.
● Carpeta services: carpeta donde gestiones las llamadas a la API. Es importante
separar la parte de la conexión con la API y la lógica de la selección de sus datos,
con la parte de la vista.
Es importante no tener llamadas a la API en las vistas, esta lógica debe estar separada,
como se explica en la estructura en la carpeta services

Evaluación
● Diseño de la página (1 punto)
● Ampliación de la página de detalles (1 punto)
● Página de juegos por tags/géneros (3 puntos)
● Página de publisher (3 puntos)
● Paginación simple (1 puntos)
● Paginación avanzada (1 puntos)
Es importante la subida del proyecto a GitHub y la web para su valoración (mirar siguiente
apartados)
Será esencial el buen diseño de la página para su evaluación. Aquel diseño que no
cumpla unos requisitos mínimos de buena estructura, uso de colores y presentación
de elementos de la página, influirá negativamente en el resto de puntos a evaluar en
esta práctica.
Entrega
La práctica será un documento PDF con enlace a los siguientes recursos:
● Un repositorio GitHub público en el que se pueda ver el contenido de tu proyecto.
● Un enlace a la página subida con Netlify o Vercel. Se aconseja el uso de Netlify o
Vercel por su facilidad de uso, pero se puede aceptar cualquier otro servicio en el
que tu web esté subida siempre y cuando tenga acceso a dicha web mediante un
enlace.
La entrega será un documento PDF con el siguiente formato:
Practica11_NombreApellidos.pdf
Nota. No subir el enlace a Github y otro enlace con acceso a la web mediante Netlify,
Vercel u otro servicio, hará que la práctica cuente como no evaluable.
